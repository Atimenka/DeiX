Возможности

Что внутри

Всё написано для DeiX: без заимствованного ядра и без libc.

Ядро на Rust

Загрузка MBR → stage2 → long mode → kernel.bin. Вытесняющая многозадачность на таймере PIT и изоляция Ring 3 для MEX-программ.

Файловые системы

/system — настоящий EROFS только для чтения, /userdata — ext2/4 для пользователей, настроек и пакетов.

Сеть и TLS

RTL8139, ARP, IPv4, ICMP, UDP, TCP, DNS и HTTP/1.1 с gzip. TLS 1.3 с проверкой сертификатов: X.509, RSA, ECDSA и 23 корневых CA.

Графика и звук

VBE 32 bpp с кириллическим шрифтом, рабочий стол с уведомлениями, Intel HDA и PC Speaker.

Dinit и диагностика

PID 1 — супервизор служб. Реестр кодов DX-*, кольцевой журнал, отчёт о сбое, который переживает перезагрузку.

DeiX Script и MEX SDK

Интерпретатор скриптов с функциями и циклами. Собственный формат программ MEX и freestanding-SDK для C/C++.

Установщик

Установка на физический диск из системы: MBR, образ /system, форматирование /userdata, проверка SHA-256 и шифрование XTS-AES-256.

Диск

Как устроен диск DeiX

Схема раскладки, не масштаб. Головка чтения наводится на область, на которую вы навели курсор.

Dev-режим

Одноразовый ключ для вашего устройства

Dev-режим включает root-оболочку и снимает гарантии целостности системы. Ключ подписан владельцем проекта и работает только на одном устройстве, один раз.

Узнайте Device ID

В DeiX выполните dev id. Команда печатает идентификатор устройства из 32 символов.

Войдите на сайт

Создайте аккаунт, подтвердите почту и вставьте Device ID в разделе «Аккаунт» → «Dev-ключ».

Получите ключ

Сайт выдаёт подписанный ключ, пока владелец принимает запросы. Ключ показывается один раз и нигде не хранится.

Включите режим

В DeiX: dev unlock КЛЮЧ, затем dev on. Сеть в этот момент не нужна.

Честная граница: это реестр устройств, а не защита от владельца машины. Исходники открыты, и проверку можно обойти.
Аккаунты

Безопасность без лишнего

Пароль хранится у Supabase Auth, сессия — в HttpOnly-cookie, формы защищены от ботов.

Двухфакторный вход

Любое TOTP-приложение: Google Authenticator, Aegis, 1Password. Восемь резервных кодов на случай потери телефона. Для панели Owner 2FA обязательна.

Проверка почты

Одноразовые адреса и домены без почтового сервера отклоняются, а письмо со ссылкой подтверждает владение адресом.

Ключи с подписью

ECDSA P-256 над Device ID и случайным nonce. Закрытый ключ хранится только на сервере, открытый вшит в систему.

Вопросы

Частые вопросы

Как запустить DeiX?

Соберите проект скриптом ./build.sh и запустите ./run.sh: система стартует в QEMU. Подробности — в README репозитория.

Зачем нужен dev-режим?

Он открывает root-оболочку для разработки и отладки. В обычной работе система неизменяема: /system смонтирован только для чтения.

Потерял телефон с кодами 2FA. Что делать?

Войдите с резервным кодом: он отключит 2FA, и её можно будет подключить заново на новом телефоне. Каждый резервный код работает один раз.

Не приходит письмо подтверждения

Проверьте папку «Спам» и запросите письмо ещё раз из аккаунта. Ссылка действует 24 часа.
