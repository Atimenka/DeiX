Features

What is inside

Everything is written for DeiX: no borrowed kernel and no libc.

A kernel in Rust

Boot chain MBR → stage2 → long mode → kernel.bin. Preemptive multitasking on the PIT timer and Ring 3 isolation for MEX programs.

File systems

/system is a real read-only EROFS; /userdata is ext2/4 for users, settings and packages.

Networking and TLS

RTL8139, ARP, IPv4, ICMP, UDP, TCP, DNS and HTTP/1.1 with gzip. TLS 1.3 with certificate checks: X.509, RSA, ECDSA and 23 root CAs.

Graphics and sound

VBE 32 bpp with a Cyrillic font, a desktop with notifications, Intel HDA and PC Speaker.

Dinit and diagnostics

PID 1 is the service supervisor. A DX-* code registry, a ring log and a crash report that survives a reboot.

DeiX Script and MEX SDK

A script interpreter with functions and loops. Our own MEX program format and a freestanding SDK for C/C++.

Installer

Install to a physical disk from within the system: MBR, the /system image, formatting /userdata, SHA-256 verification and XTS-AES-256 encryption.

Dev mode

A one-time key for your device

Dev mode enables a root shell and drops the system integrity guarantees. The key is signed by the project owner and works on one device, once.

Find your Device ID

Run dev id in DeiX. It prints the 32-character device identifier.

Sign in to the site

Create an account, verify your email and paste the Device ID under “Account” → “Dev key”.

Get the key

The site issues a signed key while the owner accepts requests. The key is shown once and is not stored anywhere.

Turn the mode on

In DeiX: dev unlock KEY, then dev on. No network is needed at that point.

An honest limit: this is a device registry, not protection against the machine owner. The source is open, and the check can be bypassed.
Accounts

Security without the fluff

The password lives in Supabase Auth, the session in an HttpOnly cookie, and forms are protected from bots.

Two-factor sign-in

Any TOTP app: Google Authenticator, Aegis, 1Password. Eight backup codes in case you lose your phone. 2FA is mandatory for the Owner panel.

Email verification

Disposable addresses and domains without a mail server are rejected, and an email with a link confirms you own the address.

Signed keys

ECDSA P-256 over the Device ID and a random nonce. The private key lives on the server only; the public key is built into the system.

Questions

Frequently asked questions

How do I run DeiX?

Build the project with ./build.sh and start ./run.sh: the system boots in QEMU. See the repository README for details.

What is dev mode for?

It opens a root shell for development and debugging. In normal use the system is immutable: /system is mounted read-only.

I lost the phone with my 2FA codes. What now?

Sign in with a backup code: it turns 2FA off, and you can enable it again on a new phone. Each backup code works once.

The confirmation email does not arrive

Check your spam folder and request the email again from your account. The link is valid for 24 hours.

Try DeiX yourself

Create an account, link a device and get a dev-mode key in a couple of minutes.
