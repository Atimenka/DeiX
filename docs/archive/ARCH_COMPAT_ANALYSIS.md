# Совместимость с пакетами Arch Linux — разбор идеи

Идея: не писать драйверы самим, а брать готовые бинарники из
репозиториев Arch/AUR и научиться их запускать.

Я проверил её на реальных пакетах, а не на предположениях. Вывод
короткий: **для драйверов идея не работает, для программ — работает,
но не для Firefox.** Ниже цифры.

## Почему это НЕ решает проблему драйверов

Ключевое недоразумение: в Linux **драйверы живут внутри ядра**, а не в
пакетах. Пакет `linux` — это уже собранное ядро Linux целиком. Взять из
него, скажем, модуль `iwlwifi.ko` и загрузить в DeiX нельзя:

- `.ko` — это ELF, слинкованный под **внутренний ABI ядра Linux**: он
  вызывает `kmalloc`, `netif_rx`, `cfg80211_*` и ещё тысячи символов,
  которых в DeiX нет и не будет без переноса половины Linux;
- ABI не стабилен даже между версиями самого Linux (модуль от 6.11 не
  грузится в 6.12);
- остаётся лицензия: DeiX под GPL-3.0, Linux — GPL-2.0-**only**.

То есть «поставить драйвер из репозитория» — это на самом деле
«запустить ядро Linux». Пакеты дают **программы пользователя**, а не
драйверы.

## Что из этого реально работает — и это ценно

Пакеты Arch содержат обычные ELF-бинарники для x86-64. Их можно
запускать, если реализовать **Linux syscall ABI**. Я замерил, сколько
именно вызовов нужно.

| Программа | Тип ELF | Уникальных syscall | Нужен ld.so |
|---|---|---|---|
| статический `hello` (write) | static | **12** | нет |
| `busybox echo` | **static** | **16** | нет |
| `bash -c 'echo test'` | dynamic | 32 | да |
| `ls` | dynamic | 25 | да |

Главная находка: **busybox в Arch собран статически** (1.3 МБ, один
файл, `Type: EXEC`, точка входа `0x417b84`). Ему не нужен динамический
линковщик — а это самый тяжёлый кусок работы. И это сразу ~400 утилит:
`sh`, `ls`, `cat`, `grep`, `vi`, `wget`.

В DeiX сейчас реализовано **5** системных вызовов (`write`, `getpid`,
`uptime`, `exit` + диагностический). До busybox не хватает ~11:
`mmap`, `munmap`, `brk`, `stat`, `arch_prctl`, `set_tid_address`,
`prctl`, `rt_sigprocmask`, `getuid`, `getgid`, `execve`.

Это **выполнимая** задача: Ring 3, TSS и syscall/sysret уже работают
(этап 4), многозадачность есть (этап 6). Не хватает загрузчика ELF и
менеджера виртуальной памяти для `mmap`/`brk`.

## Почему Firefox всё равно не получится

Проверил по настоящей базе `extra.db`:

```
firefox 155.0.1
  скачать:  88.2 МБ
  на диске: 309.9 МБ
  прямых зависимостей: 30
  ПОЛНОЕ ЗАМЫКАНИЕ ЗАВИСИМОСТЕЙ: 388 пакетов
```

388 пакетов — это glibc, GTK3, Cairo, Pango, X11 (libx11, libxcb,
libxcomposite, libxdamage, libxrandr…), D-Bus, PulseAudio, FFmpeg, NSS.
То есть чтобы запустить Firefox «из репозитория», нужно поднять:

- полный glibc с динамическим линковщиком, TLS и потоками POSIX;
- **X11-сервер** или Wayland-композитор;
- звук (ALSA/PulseAudio), шрифты (freetype/fontconfig);
- почти весь Linux syscall ABI (386 вызовов), включая `futex`,
  `epoll`, `clone`, сокеты, `/proc`.

Это не «поставить пакет» — это построить Linux-совместимую ОС. Firefox
здесь самая последняя цель, а не первая.

## Реалистичный план, если идти этим путём

1. **Загрузчик статических ELF** — разбор `PT_LOAD`, отображение
   сегментов, передача управления в Ring 3. Проверяется на
   собственном `hello_static` (12 syscall).
2. **`mmap`/`brk` + виртуальная память** — сейчас в DeiX только
   identity-mapping huge-страницами от загрузчика.
3. **~16 syscall для busybox** — и мы получаем настоящую командную
   оболочку с сотнями утилит из репозитория Arch.
4. **`pacman`-клиент** — разбор `core.db`/`extra.db` (уже проверено:
   это gzip-tar, наш `inflate.rs` его читает), скачивание по HTTP
   (TCP работает), распаковка `.pkg.tar.zst` (**нужен декодер zstd** —
   его в ядре нет).
5. Динамический линковщик + glibc — большой отдельный этап.

Пункты 1–3 дают проверяемый результат: **реальный бинарник из
репозитория Arch, исполняющийся в DeiX**. Это честная и достижимая
цель, в отличие от Firefox.

## Что проверено фактически

```bash
# репозиторий доступен по HTTP, база — обычный gzip-tar
curl -sL http://ftp.nluug.nl/os/Linux/distr/archlinux/core/os/x86_64/core.db
# 129 457 байт, tar.gz с описаниями пакетов

# пакет — tar.zst, внутри обычные ELF
busybox-1.36.1-4-x86_64.pkg.tar.zst -> usr/bin/busybox
  ELF 64-bit LSB executable, statically linked, stripped
```
