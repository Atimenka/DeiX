# Карта загрузки DEIXKIMG (версия 2)

Загрузчик DeiX и ядро лежат **файлами в `/system`** (EROFS), а не в сырой
области диска:

| Файл | Кто читает |
|------|-----------|
| `/system/boot/stage2.bin` | MBR → `0x10000` |
| `/system/boot/ramboot.bin` | MBR → `0x7E00` |
| `/system/kernel/kernel.bin` | ramboot → `0x100000` |

MBR и ramboot работают в реальном режиме через BIOS int 13h и файловых систем
не знают. Где лежат файлы, им говорит карта загрузки — один сектор **LBA 2047**.

Остальной служебный регион до `/system` (LBA 1..2046) свободен и заполнен
нулями; LBA 2048..2111 — область аварийного дампа.

## Формат сектора (все числа little-endian)

| Смещение | Размер | Поле |
|----------|--------|------|
| 0 | 8 | подпись `DEIXKIMG` |
| 8 | 4 | LBA первого участка ядра (дубль `kernel[0]`) |
| 12 | 4 | размер `kernel.bin` в байтах (с нулевым отступом до 4096) |
| 16 | 32 | SHA-256 `kernel.bin` в том же виде (с отступом) |
| 48 | 4 | версия карты = 2 |
| 52 | 4 | секторов, которые MBR читает для stage2 |
| 56 | 4 | секторов, которые MBR читает для ramboot |
| 60 | 4 | зарезервировано (0) |
| 64 | 64 | участки stage2: до 8 записей |
| 128 | 64 | участки ramboot: до 8 записей |
| 192 | 320 | участки ядра: до 40 записей |

Запись участка — `u32 lba`, `u32 sectors`; `sectors = 0` завершает таблицу.
Файл читается участками подряд, до размера из заголовка (для ядра —
`ceil(размер / 512)` секторов). Участок длиннее 65535 секторов недопустим: MBR и
ramboot читают длину как 16-битное слово.

## Кто пишет карту

* **Сборка** (`tools/make_deix_fs.py`). Файлы дополняются нулями до 4096 байт
  (иначе `mkfs.erofs` кладёт хвост файла рядом с inode, и файл перестаёт быть
  непрерывным), кладутся в EROFS без сжатия, их LBA находится по единственному
  выровненному вхождению файла в образ. Каждый файл — один участок.
* **Установщик** (`src/install.rs`). Копирует карту с загрузочного носителя
  после обнуления служебной области; `/system` копируется с теми же LBA, так
  что участки остаются верными.
* **`sysfs convert`** (`src/sysfs.rs`). Форматирование `/system` в ext2 стирает
  прежние участки. После переноса файлов конверсия берёт реальные блоки
  `boot/stage2.bin`, `boot/ramboot.bin`, `kernel/kernel.bin` из inode ext2 (файл
  может состоять из нескольких участков, так как между блоками данных ext2
  кладёт индексные блоки) и переписывает карту. Если участков больше, чем
  вмещает карта, конверсия сообщает об этом, а система без переустановки
  `/system` не загрузится.
* **Обновление** (`src/update.rs`). Региону LBA 1..2047 пакета соответствует
  новая карта; она пишется после `/system`.

## Проверки

* `src/bootmap.rs::BootMap::validate` — участки внутри `/system`, покрывают
  размер файлов, размер ядра ≤ 2 МиБ, stage2 ≤ 64 секторов, ramboot ≤ 8.
* Ядро при старте читает ядро по участкам карты и сверяет SHA-256
  (`DX-KRN-0013` при расхождении), затем сверяет файл `/system/kernel/kernel.bin`
  по имени — так проверяется, что карта указывает на настоящий файл.
* `vfs` не даёт писать, заменять и удалять `/system/boot/*` и
  `/system/kernel/*`, даже в dev-режиме на ext2.

## Что это значит на практике

* Если карта отсутствует или неверна, MBR печатает `Bad boot map`, ramboot —
  `RAMBOOT: bad boot map`; диск после этого не загрузится без переустановки.
* Окно обновления: между началом записи `/system` и записью карты (в конце)
  карта указывает на старое расположение ядра, которое новая раскладка
  `/system` могла перезаписать. Обрыв питания в этом окне оставляет диск
  незагружаемым — нужна переустановка (см. `docs/UPDATE.md`).
